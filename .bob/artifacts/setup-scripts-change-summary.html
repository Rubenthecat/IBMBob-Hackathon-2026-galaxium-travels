Branch: User-Friendly-Dependency-Install-Scripts  ·  Summary of changes that make the repo runnable right after cloning

What Problem This Solves

Before these changes, a developer who cloned the repo had to manually install Python, Node, Java 21, and Maven, figure out the right commands for their OS, copy .env files by hand, and know to pass --profile hold-service to Docker Compose to start the Java service. There was no single command to start everything.

These changes add a single bootstrap script per platform that handles all of that automatically.

How to Start the App After Cloning

macOS / Linux

./setup.sh

Windows (PowerShell)

.\setup.ps1
⚠️ Windows Local mode requires Windows 10 version 1709 or newer for winget (the auto-installer). Docker mode works on any Windows version that supports Docker Desktop.

Already have Docker running? (any platform)

docker compose up --build

The Java Hold Service now starts automatically — no extra flags needed.

What the Scripts Do

Both scripts follow the same flow:

1 Prompt Ask: Docker or Local?
2 Check Verify required tools are present
3 Install Auto-install anything missing
4 Configure Create .env if absent
5 Launch Start all services

Docker mode

  • Checks Docker binary is on PATH — prints install link if missing
  • Checks Docker daemon is running — prints clear instructions if not
  • Runs docker compose up --build

Files Changed

NEW setup.sh
  • macOS and Linux bootstrap script (227 lines)
  • OS detection — redirects Windows users to setup.ps1
  • Docker path + Local path with Homebrew / apt-get auto-install
  • Linux: prompts for sudo before any apt-get call
  • macOS: handles Homebrew OpenJDK PATH quirk automatically
NEW setup.ps1
  • Windows PowerShell equivalent (175 lines)
  • Same Docker/Local prompt
  • Uses winget for all tool installs
  • Uses Get-NetTCPConnection / Stop-Process for port cleanup (replaces Unix lsof)
  • Uses Invoke-WebRequest for health checks (replaces Unix curl)
MODIFIED docker-compose.yml
  • Removed profiles: [hold-service] from java-service
  • Java Hold Service now starts with every docker compose up — no flags needed
MODIFIED README.md
  • New Quick Start section at the top of the file
  • One-command instructions for macOS/Linux, Windows, and Docker
  • Service URL reference table
  • Windows 10 1709+ note for winget
CI .github/workflows/setup-test.yml
  • New GitHub Actions workflow — runs on every push or PR touching setup scripts or any service
  • Manually triggerable from the GitHub Actions tab with a dropdown to include/exclude the macOS job

CI Workflow — 3 Jobs

The workflow validates the scripts on real, clean GitHub-hosted runners so regressions are caught before they reach anyone cloning the repo.

JobRunnerTriggerWhat it validates
Docker mode (Ubuntu) ubuntu-latest push, pull_request, manual Runs docker compose up --build, health-checks all 4 services: backend (:8001), frontend (:5173), Java Hold Service (:8082), postgres
Local mode (Ubuntu) ubuntu-latest push, pull_request, manual Mirrors setup.sh local path: apt-get installs, Python venv, pip install, npm install, starts backend + Java Hold Service natively, verifies both health endpoints respond
Local mode (macOS) macos-latest manual only Validates macOS-specific paths in setup.sh: Homebrew installs (python@3.11, node, openjdk@21, maven), OpenJDK PATH fix via brew --prefix, Java version check, backend + Java Hold Service startup
